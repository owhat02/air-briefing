# Air Briefing

서울시 25개 자치구의 대기환경 데이터 수집·검증 및 일일 브리핑 제공 서비스

## 목표 기능

- 서울시 25개 자치구 대기환경 데이터 수집 및 측정값 검증
- 수집 시점별 스냅샷 저장 및 과거 기록 조회
- 자치구별 대기질 등급·통합지수 기반 주의 지역 요약
- 직전 수집 결과 대비 대기질 변화 및 경고 정보 제공
- REST API·Swagger 기반 데이터 수집, 스냅샷 조회, 브리핑 생성

## 데이터 출처

[서울 열린데이터광장](https://data.seoul.go.kr/dataList/OA-1200/S/1/datasetView.do)의 **서울시 실시간 자치구별 대기환경 현황(OA-1200)** 데이터 활용. `ListAirQualityByDistrictService` API 기반 측정 시각·자치구·통합 대기환경지수·등급·미세먼지 및 대기오염물질 측정값 수집. 데이터 제공 주기 약 1시간.

서울 API 인증키의 서버 환경변수(`SEOUL_OPENAPI_KEY`) 관리 및 코드·공개 저장소 미포함

## 기술 스택

| 영역 | 기술 |
|---|---|
| 언어 | Java |
| 백엔드 | Spring Boot, Spring Data JPA |
| 데이터베이스 | PostgreSQL |
| 로컬 인프라 | Docker Compose |
| API | REST, JSON, Swagger UI |

## 구현 목표

1. **외부 데이터 수집** — Spring Boot 서버에서 서울 열린데이터광장 API 호출. 연결·응답 시간 제한 및 타임아웃·서버 오류 재시도 적용.
2. **데이터 검증 및 저장** — 자치구·측정 시각·등급·통합지수 등 필수 항목 검증. 정상 데이터의 스냅샷·자치구별 행 저장. 결측 측정값의 null 처리 및 수집 건수·탈락률 기록.
3. **브리핑 생성** — 스냅샷 기반 리포트 작업 생성. Spring 단일 `@Scheduled` 워커의 대기 작업 처리. 나쁨·매우 나쁨 지역, 직전 스냅샷 대비 지수 변화, 경고 건수 계산. 동일 스냅샷 중복 요청의 기존 작업 재사용.
4. **조회 API 제공** — 수집 실행, 스냅샷 목록·상세, 리포트 작업 상태·결과를 위한 REST API. 날짜별 스냅샷 조회 및 최소 화면 확장.
5. **로컬 실행 환경 구성** — Docker Compose 기반 Spring Boot 애플리케이션·PostgreSQL 통합 실행 환경.

## 브리핑에 담을 정보

- 수집 시각과 정상 수집된 자치구 수
- 데이터 검증 탈락률
- 통합지수가 높은 나쁨·매우 나쁨 지역 상위 목록
- 경고 대상 지역 수
- 직전 스냅샷과 비교한 평균 지수 변화
